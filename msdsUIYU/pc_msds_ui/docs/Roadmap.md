# 产品路线图 (Roadmap) - MSDS 管理文件系统

## 1. 路线图概述

本文档旨在规划“MSDS 管理文件系统”从最小可行产品 (MVP) 到后续主要版本的演进路径。路线图将明确各阶段的核心目标、主要功能、预期交付时间以及关键里程碑，为产品团队提供清晰的开发指引和优先级排序。

本路线图将根据市场反馈、用户需求变化以及业务发展战略进行定期回顾和调整。

**核心目标**: 
- **短期 (MVP)**: 快速上线核心功能，验证产品价值，收集早期用户反馈。
- **中期 (V2.0)**: 完善核心体验，扩展辅助功能，提升系统稳定性和易用性。
- **长期 (V3.0+)**: 探索增值服务，拓展平台能力，构建生态系统。

## 2. 版本规划策略

- **MVP (Minimum Viable Product) - V1.0**: 聚焦于解决用户最核心的痛点——MSDS的电子化存储、快速检索和便捷查阅。优先保证核心功能的稳定可用。
- **迭代版本 (V1.x)**: 基于MVP的用户反馈，快速修复Bug，优化体验，补充少量高优先级的小功能。
- **主要版本 (V2.0, V3.0)**: 引入重要的新功能模块，提升系统性能和安全性，拓展产品边界。
- **敏捷开发**: 采用敏捷开发模式，小步快跑，持续交付，定期回顾和调整计划。

## 3. 详细版本规划

### 3.1 MVP (V1.0) - 核心功能上线 (预计时间: T0 + 3个月)

**版本目标**: 实现MSDS文档的电子化管理与基础查阅功能，满足实验室科研人员和管理员的基本需求，验证产品核心价值。

**核心功能**: 
-   **MSDS 数据管理**:
    -   [P0] MSDS 文件上传 (支持PDF, DOCX, TXT)
    -   [P0] MSDS 元数据编辑 (化学品名称, CAS号, 供应商, 版本号)
    -   [P0] MSDS 版本控制 (基础版：新版覆盖旧版，或简单标记最新)
-   **MSDS 检索与查阅**:
    -   [P0] 关键词搜索 (按化学品名称, CAS号)
    -   [P0] MSDS 在线预览 (PDF为主)
    -   [P0] MSDS 文件下载
-   **用户管理**:
    -   [P0] 基础用户注册与登录 (管理员手动创建用户，用户可修改密码)
    -   [P0] 简单角色区分 (管理员 vs 普通用户)
-   **系统基础**:
    -   [P0] PC客户端 (Windows 优先，macOS 次之)
    -   [P0] 本地文件存储/简单数据库存储MSDS信息

**非功能性需求关注点**: 
-   基本可用性与稳定性。
-   核心操作的性能（搜索、预览）。

**排除功能 (延后)**: 批量导入、高级搜索、自定义分类标签、复杂权限管理、通知提醒、操作日志、GHS信息展示等。

### 3.2 V1.1 - MVP优化与反馈迭代 (预计时间: T0 + 4个月)

**版本目标**: 根据MVP用户反馈，修复已知Bug，优化核心流程体验，补充少量高价值小功能。

**主要内容**: 
-   [P0] Bug修复与性能优化 (基于MVP反馈)。
-   [P1] 搜索功能增强 (如支持模糊搜索，优化结果排序)。
-   [P1] 预览体验提升 (如支持更多格式，预览内搜索)。
-   [P1] 简单的MSDS分类/标签功能 (手动添加)。
-   [P2] 基础的操作日志记录 (关键操作)。

### 3.3 V2.0 - 功能完善与体验提升 (预计时间: T0 + 8个月)

**版本目标**: 全面提升产品易用性和管理效率，引入更完善的MSDS管理和协作功能，增强系统安全性与合规性。

**核心功能**: 
-   **MSDS 数据管理增强**:
    -   [P0] 完善的MSDS版本控制 (保留历史版本，可追溯)
    -   [P0] 批量导入MSDS功能 (支持CSV模板+文件)
    -   [P1] MSDS自定义字段与分类体系
    -   [P1] MSDS定期复审与过期提醒机制
-   **MSDS 检索与查阅增强**:
    -   [P0] 高级搜索 (多条件组合搜索，按元数据字段搜索)
    -   [P1] 全文检索引擎引入 (提升搜索准确度和范围)
    -   [P1] MSDS收藏/常用列表功能
-   **用户与权限管理**:
    -   [P0] 完善的角色与权限管理体系 (自定义角色，细粒度权限分配)
    -   [P1] 用户组管理
-   **通知与提醒**:
    -   [P1] MSDS更新通知 (邮件或系统内通知)
-   **日志与审计**:
    -   [P0] 详细的操作审计日志 (符合合规要求)
-   **安全增强**:
    -   [P0] 数据传输加密 (HTTPS)
    -   [P1] 数据存储加密 (可选)
-   **其他**: 
    -   [P1] macOS客户端功能对齐Windows版
    -   [P1] **GHS 标签与安全卡片生成**: 根据MSDS数据，一键生成符合规范的GHS标签和简明安全操作卡片。
    -   [P2] GHS信息辅助展示 (如危险象形图)

**非功能性需求关注点**: 
-   系统安全性、稳定性、可扩展性。
-   大规模数据下的性能表现。

### 3.4 V2.x - 持续迭代与生态拓展准备 (预计时间: T0 + 9-12个月)

**版本目标**: 持续优化V2.0功能，探索与实验室其他系统集成的可能性，为未来的平台化发展做准备。

**可能方向**: 
-   [P1] **化学品库存集成**: 与实验室现有库存管理系统进行API级别集成，实现MSDS与化学品库存信息的双向关联。
-   [P1] **高级报告与审计支持**: 提供可定制的报告功能，支持生成化学品使用、MSDS查阅、安全审计等报告。
-   [P1] API接口初步设计与开放 (用于第三方集成)
-   [P2] 与LIMS/ELN系统集成POC (概念验证)
-   [P2] 移动端查阅方案探索 (如响应式Web或PWA)
-   [P2] 多语言支持框架搭建

### 3.5 V3.0 及以后 - 智能化与平台化 (预计时间: T0 + 12个月以上)

**版本目标**: 引入智能化特性，构建MSDS管理生态，提供更广泛的实验室安全服务。

**可能方向**: 
-   **智能化**: 
    -   MSDS智能解析与信息提取 (OCR, NLP技术)
    -   化学品风险评估辅助
    -   智能推荐相关安全操作规程
-   **平台化**: 
    -   SaaS服务模式
    -   供应商MSDS数据接口对接
    -   实验室安全培训模块
    -   社区与知识共享

## 5. 详细时间线计划 (里程碑)

*(注: T0 为项目启动日期，具体日期需根据实际情况确定)*

- **T0**: 项目启动，团队组建，需求详细评审。
- **T0 + 2周**: MVP技术选型与架构设计完成。
- **T0 + 1个月**: MVP核心模块开发过半，原型演示。
- **T0 + 2.5个月**: MVP功能开发完成，进入测试阶段。
- **T0 + 3个月**: **里程碑1: MVP (V1.0) 发布**。启动早期用户试用与反馈收集。
- **T0 + 3.5个月**: V1.1需求确认与开发启动。
- **T0 + 4个月**: **里程碑2: V1.1 发布**。持续收集反馈，规划V2.0。
- **T0 + 4.5个月**: V2.0详细设计与开发启动。
- **T0 + 7个月**: V2.0主要功能模块开发完成，集成测试开始。
- **T0 + 8个月**: **里程碑3: V2.0 发布**。
- **T0 + 9-12个月**: V2.x版本持续迭代，根据市场情况调整后续计划。
- **T0 + 12个月以上**: 评估V3.0开发可行性与方向。

## 7. 风险管理

- **需求变更风险**: 
    -   **应对**: 建立清晰的需求变更管理流程；MVP阶段聚焦核心，避免范围蔓延；通过快速迭代响应变化。
- **技术实现风险**: 
    -   **应对**: 关键技术点进行预研和POC验证；选择成熟稳定的技术栈；代码评审和单元测试。
- **进度延期风险**: 
    -   **应对**: 制定合理的开发计划和缓冲时间；加强项目进度跟踪和沟通；及时调整资源分配。
- **用户接受度风险**: 
    -   **应对**: MVP阶段尽早让真实用户参与测试并收集反馈；持续关注用户体验；加强用户培训和引导。
- **竞争风险**: 
    -   **应对**: 持续关注竞品动态；突出产品差异化优势；快速响应市场变化。
- **数据安全风险**: 
    -   **应对**: 严格遵守安全开发规范；加强数据加密和权限控制；定期进行安全审计和漏洞扫描。
