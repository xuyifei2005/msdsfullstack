## 🔍 问题描述

### 现象
- `npm start` 命令启动过程异常缓慢
- 开发服务器长时间停留在 `cross-env UMI_ENV=dev max dev` 阶段
- 删除 `node_modules` 时出现 `Directory not empty` 错误
- 编译过程中出现模块解析错误：`Module not found: Error: Can't resolve '/app/node_modules/@umijs/react-refresh-webpack-plugin/client/ReactRefreshEntry.js'`

### 错误日志
```bash
# 删除node_modules失败
rm: cannot remove 'node_modules/...': Directory not empty

# 模块解析错误
Module not found: Error: Can't resolve '/app/node_modules/@umijs/react-refresh-webpack-plugin/client/ReactRefreshEntry.js'
```

---

## 🔧 问题分析

### 根本原因
1. **依赖冲突**: `node_modules` 中存在版本冲突或损坏的依赖包
2. **缓存问题**: npm缓存可能包含过期或损坏的包信息
3. **文件锁定**: 某些进程可能正在使用 `node_modules` 中的文件
4. **模块路径错误**: `@umijs/react-refresh-webpack-plugin` 包的路径解析问题

### 影响范围
- 开发环境启动失败
- 热重载功能异常
- 开发效率受影响

---

## ✅ 解决方案

### 步骤1: 停止运行中的进程
```bash
# 停止npm start进程
# 使用stop_command工具停止command_id对应的进程
```

### 步骤2: 强制清理依赖
```bash
# 强制删除node_modules目录
rm -rf node_modules

# 删除package-lock.json（可选，用于重新生成依赖树）
rm -f package-lock.json
```

### 步骤3: 重新安装依赖
```bash
# 清理npm缓存
npm cache clean --force

# 重新安装所有依赖
npm install
```

### 步骤4: 验证修复
```bash
# 启动开发服务器
npm start
```

## 🔮 预防措施

### 1. 依赖管理最佳实践
- 定期更新依赖包到稳定版本
- 使用 `package-lock.json` 锁定依赖版本
- 避免全局安装过多包

### 2. 开发环境维护
- 定期清理npm缓存：`npm cache clean --force`
- 监控依赖包的安全漏洞
- 保持Node.js和npm版本更新

### 3. 故障排查流程
1. 检查进程是否正常停止
2. 清理缓存和临时文件
3. 重新安装依赖
4. 验证配置文件完整性
