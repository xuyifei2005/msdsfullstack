## 📝 完整编译步骤

### 第 1 步：检查容器状态
```bash
# 查看前端容器是否运行
docker ps | grep msdsfrontend

# 如果容器未运行，启动容器
cd D:\XUYIFEI\XUPROJECTS\msdsfullstack\msdsdocker
docker-compose up -d msdsfrontend
```

### 第 2 步：进入前端容器
```bash
# 进入容器内部shell
docker-compose exec msdsfrontend bash

# 或者直接执行命令
docker exec -it msdsfrontend bash
```

### 第 3 步：检查项目目录和依赖
```bash
# 在容器内执行
cd /app

# 查看项目文件
ls -la

# 检查Node.js版本（要求>=18.0.0）
node --version

# 检查npm版本
npm --version

# 查看已安装的依赖
ls -la node_modules
```

### 第 4 步：清理缓存和旧文件（重要）
```bash
# 在容器内执行完整清理
cd /app

# 删除编译产物
rm -rf dist
rm -rf .umi
rm -rf .umi-production

# 清理npm缓存
npm cache clean --force

# 如果需要完全重装依赖
rm -rf node_modules
rm -f package-lock.json
```

### 第 5 步：安装依赖
```bash
# 在容器内执行
cd /app

# 安装所有依赖（推荐使用npm ci以保证依赖一致性）
npm install

# 或者使用npm ci（更快，更可靠）
npm ci
```

**预计时间**：2-5分钟（取决于网络速度和缓存情况）

### 第 6 步：执行编译
```bash
# 在容器内执行

# 生产环境编译（压缩优化）
npm run build:prod

# 或者普通编译
npm run build

# 开发环境编译（不压缩，带source map）
npm run build
```

**预计时间**：
- 开发编译：1-3分钟
- 生产编译：3-8分钟（带优化和压缩）

### 第 7 步：验证编译结果
```bash
# 在容器内执行
cd /app

# 查看dist目录
ls -lh dist/

# 查看编译产物大小
du -sh dist/

# 验证index.html是否生成
cat dist/index.html | head -20
```

**成功标志**：
- `dist/` 目录存在
- `dist/index.html` 文件存在
- `dist/umi.js` 或 `dist/*.js` 文件存在
- 控制台输出 `Build success`

## 📖 编译脚本说明

### package.json中的编译脚本

#### 开发模式脚本
```json
{
  "scripts": {
    "start": "cross-env UMI_ENV=dev max dev",
    "start:dev": "cross-env REACT_APP_ENV=dev MOCK=none UMI_ENV=dev max dev",
    "start:no-mock": "cross-env MOCK=none UMI_ENV=dev max dev",
    "start:pre": "cross-env REACT_APP_ENV=pre UMI_ENV=dev max dev",
    "start:test": "cross-env REACT_APP_ENV=test MOCK=none UMI_ENV=dev max dev"
  }
}
```

- **start**: 默认开发模式，带Mock数据
- **start:dev**: 开发环境，不使用Mock，连接开发后端
- **start:no-mock**: 不使用Mock数据
- **start:pre**: 预生产环境
- **start:test**: 测试环境

#### 生产编译脚本
```json
{
  "scripts": {
    "build": "max build",
    "build:prod": "cross-env REACT_APP_ENV=prod max build",
    "preview": "npm run build && max preview --port 8000"
  }
}
```

- **build**: 默认编译
- **build:prod**: 生产环境编译（压缩、优化、去除source map）
- **preview**: 编译后本地预览

#### 其他实用脚本
```json
{
  "scripts": {
    "analyze": "cross-env ANALYZE=1 max build",
    "lint": "npm run lint:js && npm run lint:prettier && npm run tsc",
    "lint:fix": "eslint --fix --cache --ext .js,.jsx,.ts,.tsx --format=pretty ./src"
  }
}
```

- **analyze**: 编译并生成包体积分析报告
- **lint**: 代码质量检查
- **lint:fix**: 自动修复代码格式问题

### 推荐使用的编译命令

| 场景 | 命令 | 说明 |
|------|------|------|
| **生产部署** | `npm run build:prod` | 完整优化，体积最小 |
| **快速验证** | `npm run build` | 普通编译，较快 |
| **开发调试** | `npm run start:no-mock` | 热更新，实时预览 |
| **包体积分析** | `npm run analyze` | 分析依赖大小 |

### 问题7：npm install失败 - ENOTEMPTY错误（Docker+WSL2常见问题）⚠️

**错误信息**：
```
npm error code ENOTEMPTY
npm error syscall rmdir
npm error path /app/node_modules/@umijs/mako/node_modules/less/dist
npm error errno -39
npm error ENOTEMPTY: directory not empty, rmdir '/app/node_modules/@umijs/mako/node_modules/less/dist'
```

**问题原因**：
这是Docker容器+WSL2+Windows文件系统共享环境下的常见问题，主要原因：
1. **文件系统延迟**：WSL2和Windows文件系统之间的交互延迟
2. **文件锁定**：某些文件被多个进程占用
3. **嵌套依赖过深**：node_modules中的深层嵌套导致删除失败
4. **npm清理机制**：npm在更新依赖时清理旧文件失败

**解决方案**：

#### 🌟 方案A：使用npm ci替代npm install（最推荐）
```bash
# 在容器内执行
cd /app

# 仅删除编译产物，保留node_modules
rm -rf dist .umi .umi-production

# 使用 npm ci（会自动清理并严格按package-lock.json安装）
npm ci
```

**为什么npm ci更好？**
- 自动清理node_modules并重新安装
- 速度比npm install快30-50%
- 严格按照package-lock.json安装，确保依赖一致性
- 适合CI/CD环境和Docker容器

#### 方案B：完全重建容器和命名卷
```bash
# 在主机PowerShell执行
cd D:\XUYIFEI\XUPROJECTS\msdsfullstack\msdsdocker

# 停止并删除前端容器
docker-compose stop msdsfrontend
docker-compose rm -f msdsfrontend

# 删除node_modules命名卷（彻底清理）
docker volume rm msdsdocker_msdsnode_modules

# 重新启动容器（会自动重新创建卷）
docker-compose up -d msdsfrontend

# 等待容器启动完成，然后编译
docker-compose exec msdsfrontend bash -c "cd /app && npm ci && npm run build:prod"
```

#### 方案C：在容器内手动强制清理
```bash
# 进入容器
docker-compose exec msdsfrontend bash

# 在容器内执行强制清理
cd /app

# 使用find命令递归删除（更彻底）
find node_modules -mindepth 1 -maxdepth 1 -exec rm -rf {} +

# 或使用 rm -rf 多次尝试
rm -rf node_modules
rm -rf node_modules
rm -rf node_modules

# 清理npm缓存
npm cache clean --force

# 重新安装
npm ci
```

#### 方案D：使用--legacy-peer-deps（跳过peer依赖检查）
```bash
# 如果是peer依赖冲突导致的ENOTEMPTY
npm install --legacy-peer-deps

# 或者使用强制安装
npm install --force
```

#### 方案E：修改Docker Compose配置（长期解决方案）

如果问题频繁出现，可以修改 `docker-compose.yml`，使用命名卷而非绑定挂载：

```yaml
msdsfrontend:
  volumes:
    - ../msdsPC/ruoyi-MsdsPc-react/react-ui:/app
    # 使用命名卷来管理node_modules（推荐）
    - msdsnode_modules:/app/node_modules
```

这样可以避免WSL2和Windows文件系统之间的冲突。

**预防措施**：

1. **优先使用npm ci**：
   ```bash
   # 代替 npm install
   npm ci
   ```

2. **避免频繁删除node_modules**：
   ```bash
   # 仅清理编译产物
   rm -rf dist .umi .umi-production
   
   # 然后npm ci会自动处理依赖更新
   npm ci
   ```

3. **定期清理Docker卷**：
   ```bash
   # 每周清理一次未使用的卷
   docker volume prune -f
   ```

4. **使用.dockerignore**：
   确保 `node_modules` 在 `.dockerignore` 中，避免从主机复制到容器：
   ```
   node_modules
   dist
   .umi
   .umi-production
   ```

**快速恢复命令**（推荐）：
```bash
# 一键清理并重新编译（主机执行）
cd D:\XUYIFEI\XUPROJECTS\msdsfullstack\msdsdocker

docker-compose exec msdsfrontend bash -c "
  cd /app && \
  rm -rf dist .umi .umi-production && \
  npm cache clean --force && \
  npm ci && \
  npm run build:prod
"
```

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /usr/share/nginx/html;
    index index.html;

    # 处理SPA路由
    location / {
        try_files $uri $uri/ /index.html;

    # API代理
    location /api {
        proxy_pass http://msdsbackend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

    gzip_types text/plain text/css application/json application/javascript;
    gzip_min_length 1000;
}
```

### 方案三：CI/CD自动化部署

#### GitHub Actions示例
```yaml
name: Frontend Build and Deploy

on:
  push:
    branches: [ main, develop ]

jobs:
  build:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v3
    
    - name: Setup Node.js
      uses: actions/setup-node@v3
      with:
        node-version: '18'
        cache: 'npm'
        cache-dependency-path: react-ui/package-lock.json
    
    - name: Install dependencies
      run: |
        cd react-ui
        npm ci
    
    - name: Build production
      run: |
        cd react-ui
        npm run build:prod
    
    - name: Upload artifact
      uses: actions/upload-artifact@v3
      with:
        name: dist
        path: react-ui/dist
    
    - name: Deploy to server
      uses: easingthemes/ssh-deploy@main
      env:
        SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
        REMOTE_HOST: ${{ secrets.REMOTE_HOST }}
        REMOTE_USER: ${{ secrets.REMOTE_USER }}
        SOURCE: "react-ui/dist/"
        TARGET: "/var/www/html/"
```
