## 2. 服务器环境准备

### 2.1 系统要求

- **CPU**: 2核及以上（推荐4核）
- **内存**: 4GB及以上（推荐8GB）
- **硬盘**: 50GB及以上（推荐100GB SSD）
- **操作系统**: Linux (Ubuntu 20.04+ / CentOS 7+)

### 2.2 安装Docker和Docker Compose

#### 在Ubuntu上安装

```bash
# 更新软件包索引
sudo apt-get update

# 安装依赖
sudo apt-get install -y \
    apt-transport-https \
    ca-certificates \
    curl \
    gnupg \
    lsb-release

# 添加Docker官方GPG密钥
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# 设置stable仓库
echo \
  "deb [arch=amd64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 安装Docker Engine
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io

# 安装Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/download/v2.20.0/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose

# 验证安装
docker --version
docker-compose --version
```

#### 在CentOS上安装

```bash
# 安装依赖
sudo yum install -y yum-utils device-mapper-persistent-data lvm2

# 添加Docker仓库
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 安装Docker
sudo yum install -y docker-ce docker-ce-cli containerd.io

# 启动Docker
sudo systemctl start docker
sudo systemctl enable docker

# 安装Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/download/v2.20.0/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
```

### 2.3 配置防火墙

```bash
# Ubuntu (使用ufw)
sudo ufw allow 22/tcp     # SSH
sudo ufw allow 80/tcp     # HTTP
sudo ufw allow 443/tcp    # HTTPS
sudo ufw enable

# CentOS (使用firewalld)
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload
```

### 2.4 创建项目目录

```bash
# 创建项目根目录
sudo mkdir -p /opt/msds
sudo mkdir -p /opt/msds-backup

# 设置权限
sudo chown -R $USER:$USER /opt/msds
sudo chown -R $USER:$USER /opt/msds-backup
```

您已经在阿里云申请了免费SSL证书，证书信息：
- 域名: flymsds.cn
- 证书类型: 免费DV证书

1. 登录阿里云控制台
2. 进入SSL证书管理页面: https://yundunnext.console.aliyun.com/?p=cas#/overview/cn-hangzhou
3. 下载Nginx格式的证书
4. 解压后得到两个文件：

   - `flymsds.cn.key` (私钥文件)

### 3.3 上传证书到服务器

```bash
# 创建SSL证书目录

# 使用scp上传证书（从本地执行）

scp flymsds.cn.key root@39.107.211.72:/opt/msds/nginx/ssl/

# 或者使用解压后的证书包
unzip flynginx19760595_flymsds.cn_nginx.zip
cd nginx
scp flymsds.cn.pem root@39.107.211.72:/opt/msds/nginx/ssl/
scp flymsds.cn.key root@39.107.211.72:/opt/msds/nginx/ssl/

# 设置证书文件权限
chmod 600 /opt/msds/nginx/ssl/flymsds.cn.key
```

#### 手动备份

```bash
cd /opt/msds/msdsdocker

# 完整备份

# 备份单个数据库
./backup-restore.sh database msds_prod

# 增量备份

```

#### 自动备份（推荐）

设置定时任务：

```bash
# 编辑crontab
crontab -e

# 添加以下内容（每天凌晨2点自动备份）
0 2 * * * /opt/msds/msdsdocker/backup-restore.sh auto >> /var/log/msds-backup.log 2>&1

# 每周日凌晨3点执行完整备份
0 3 * * 0 /opt/msds/msdsdocker/backup-restore.sh full weekly >> /var/log/msds-backup.log 2>&1

# 每月1号凌晨4点执行月度备份
0 4 1 * * /opt/msds/msdsdocker/backup-restore.sh full monthly >> /var/log/msds-backup.log 2>&1
```

## 7. 故障排查

### 7.1 常见问题

#### 问题1: 容器无法启动

**症状**: 容器启动后立即退出

**排查步骤**:
```bash
# 查看容器日志
docker logs msdsbackend-prod

# 检查配置文件
cat .env.prod

# 验证环境变量
docker-compose -f docker-compose.prod.yml config
```

**常见原因**:
- 数据库密码配置错误
- 端口被占用
- 内存不足

#### 问题2: 无法访问网站

**症状**: 浏览器无法打开 https://flymsds.cn

**排查步骤**:
```bash
# 1. 检查Nginx容器状态
docker ps | grep nginx

# 2. 检查Nginx配置
docker exec msdsnginx-prod nginx -t

# 3. 查看Nginx错误日志
docker logs msdsnginx-prod

# 4. 检查端口映射
netstat -tulpn | grep :443
netstat -tulpn | grep :80

# 5. 测试后端连接
curl http://localhost:8080/actuator/health
```

**可能原因**:
- DNS未解析（需要等待DNS生效）
- 防火墙阻止
- SSL证书配置错误
- 后端服务未启动

#### 问题3: 数据库连接失败

**症状**: 后端日志显示数据库连接错误

**排查步骤**:
```bash
# 1. 检查MySQL容器
docker ps | grep mysql

# 2. 测试数据库连接
docker exec -it msdsmysql-prod mysql -u root -p

# 3. 检查数据库日志
docker logs msdsmysql-prod

# 4. 验证网络连接
docker network inspect msdsdocker_msds_network
```

**解决方法**:
```bash
# 重启MySQL容器
docker-compose -f docker-compose.prod.yml restart msdsmysql

# 检查环境变量
cat .env.prod | grep MYSQL
```

#### 问题4: 内存不足

**症状**: 容器频繁重启或OOM错误

**排查步骤**:
```bash
# 检查系统内存
free -h

# 查看容器内存使用
docker stats --no-stream

# 查看系统日志
dmesg | grep -i oom
```

**解决方法**:
- 增加服务器内存
- 调整JVM参数（在.env.prod中修改JAVA_OPTS）
- 限制容器内存使用

### 7.2 性能优化

#### 优化JVM参数

编辑 `.env.prod`:
```bash
# 根据服务器内存调整
JAVA_OPTS=-Xms2048m -Xmx4096m -XX:+UseG1GC -XX:MaxGCPauseMillis=200
```

#### 优化MySQL配置

创建 `mysql/conf.d/my.cnf`:
```ini
[mysqld]
# 连接数
max_connections=500

# 缓冲池大小（服务器内存的70-80%）
innodb_buffer_pool_size=2G

# 日志文件大小
innodb_log_file_size=512M

# 查询缓存
query_cache_size=64M
query_cache_type=1
```

#### 优化Nginx配置

已在 `nginx.prod.conf` 中配置：
- Gzip压缩
- 静态文件缓存
- 连接池优化

## 8. 安全建议

### 8.1 必须执行的安全措施

#### 1. 修改默认密码

```bash
# 修改数据库密码
docker exec -it msdsmysql-prod mysql -u root -p
# 在MySQL中执行：
ALTER USER 'root'@'%' IDENTIFIED BY 'new_strong_password';
FLUSH PRIVILEGES;

# 修改应用管理员密码
# 登录系统后在 个人中心 -> 修改密码
```

#### 2. 配置防火墙

```bash
# 只开放必要端口
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

#### 3. 禁止root SSH登录

编辑 `/etc/ssh/sshd_config`:
```bash
PermitRootLogin no
PasswordAuthentication no  # 使用密钥登录
```

重启SSH服务:
```bash
sudo systemctl restart sshd
```

#### 4. 设置定期备份

已通过cron配置自动备份，确保备份正常执行：
```bash
# 检查备份日志
tail -f /var/log/msds-backup.log

# 手动测试备份
./backup-restore.sh full
```

### 8.2 推荐的安全措施

#### 1. 安装Fail2Ban（防暴力破解）

```bash
sudo apt-get install fail2ban
sudo systemctl enable fail2ban
sudo systemctl start fail2ban
```

#### 2. 启用Docker日志轮转

创建 `/etc/docker/daemon.json`:
```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

重启Docker:
```bash
sudo systemctl restart docker
```

#### 3. 定期更新系统

```bash
# Ubuntu
sudo apt-get update
sudo apt-get upgrade

# CentOS
sudo yum update
```

#### 4. 监控异常登录

```bash
# 查看SSH登录日志
sudo tail -f /var/log/auth.log

# 查看失败的登录尝试
sudo grep "Failed password" /var/log/auth.log
```
