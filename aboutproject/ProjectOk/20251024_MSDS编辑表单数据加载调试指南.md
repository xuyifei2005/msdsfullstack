# MSDS编辑表单数据加载调试指南

## 问题现象
用户打开MSDS的16节编辑表单时，表单字段为空，没有显示数据库中已有的数据。

## 调试步骤

### 1. 浏览器控制台调试

打开MSDS列表页面，按F12打开浏览器开发者工具，切换到Console选项卡。

#### 步骤1：点击"16节编辑"按钮
在控制台应该看到：
```
🔍 [MsdsList] 点击16节编辑按钮，record: {id: 164, productName: "...", ...}
🔍 [MsdsList] record.id: 164
```

**检查点**:
- ✅ record对象是否包含数据？
- ✅ record.id是否有值？
- ❌ 如果没有看到日志，说明onClick事件未触发

#### 步骤2：编辑表单打开时
控制台应该看到：
```
🔍 [MsdsList] 渲染MsdsStepForm, currentRow: {id: 164, ...}
🔍 [MsdsList] 传递msdsId: 164
```

**检查点**:
- ✅ currentRow是否有值？
- ✅ msdsId是否正确传递？

#### 步骤3：MsdsStepForm组件加载
控制台应该看到：
```
🔍 [MsdsStepForm] 开始加载MSDS数据, msdsId: 164
```

**检查点**:
- ✅ msdsId是否正确接收？
- ❌ 如果看到"msdsId为空，跳过数据加载"，说明参数传递有问题

#### 步骤4：API调用响应
控制台应该看到：
```
🔍 [MsdsStepForm] API响应数据: {
  main: {code: 200, data: {...}},
  hazard: {code: 200, data: {...}},
  component: {code: 200, data: {...}}
}
✅ [MsdsStepForm] 加载基本信息: {id: 164, productName: "...", ...}
```

**检查点**:
- ✅ API是否返回200状态码？
- ✅ data字段是否有内容？
- ❌ 如果code不是200，检查后端API
- ❌ 如果data为空，检查数据库

#### 步骤5：数据组装
控制台应该看到：
```
📦 [MsdsStepForm] 组装后的完整数据: {
  basic: {...},
  hazard: {...},
  component: {...}
}
✅ [MsdsStepForm] 步骤1(basic)已有数据
✅ [MsdsStepForm] 步骤2(hazard)已有数据
...
✅ [MsdsStepForm] 数据加载完成，已加载章节数: 3
```

**检查点**:
- ✅ completeData是否包含各章节数据？
- ✅ 显示了多少个章节已有数据？

#### 步骤6：Step1表单接收数据
控制台应该看到：
```
🔍 [Step1BasicInfo] 接收到data prop: {id: 164, productName: "...", ...}
📝 [Step1BasicInfo] 设置表单值: {productName: "...", casNumber: "...", ...}
✅ [Step1BasicInfo] 表单值已设置
```

**检查点**:
- ✅ data prop是否接收到数据？
- ✅ form.setFieldsValue是否被调用？
- ❌ 如果显示"data为空"，说明数据传递有问题

### 2. 网络请求调试

在浏览器开发者工具的Network选项卡中：

1. 点击"16节编辑"按钮
2. 查看是否有以下请求：
   - `GET /api/system/msds/164`
   - `GET /api/system/msds/hazard/164`  
   - `GET /api/system/msds/component/164`
   - ...等16个请求

**检查点**:
- ✅ 请求是否发出？
- ✅ 请求URL是否正确？
- ✅ 响应状态码是否为200？
- ✅ 响应数据是否包含内容？

### 3. 后端API测试

使用curl或Postman测试后端API：

```bash
# 获取MSDS主信息
curl http://localhost:18080/system/msds/164 \
  -H "Authorization: Bearer YOUR_TOKEN"

# 获取危险性信息
curl http://localhost:18080/system/msds/hazard/164 \
  -H "Authorization: Bearer YOUR_TOKEN"
```

**检查点**:
- ✅ API是否返回数据？
- ✅ 数据格式是否正确？
- ✅ 字段名是否为驼峰命名？

### 4. 数据库数据验证

```sql
-- 检查主表数据
SELECT id, product_name, cas_number, company_name 
FROM msds_main 
WHERE id = 164;

-- 检查子表数据
SELECT id, msds_id, emergency_overview 
FROM msds_hazard 
WHERE msds_id = 164;

SELECT id, msds_id, component_name 
FROM msds_component 
WHERE msds_id = 164;
```

**检查点**:
- ✅ 主表数据是否存在？
- ✅ 子表数据是否存在？
- ✅ msds_id是否等于主表的id？

## 常见问题排查

### 问题1：msdsId为undefined
**现象**：控制台显示"msdsId为空，跳过数据加载"

**可能原因**:
1. currentRow未设置
2. record.id为undefined
3. 表格数据rowKey配置错误

**解决方法**:
```typescript
// 检查表格的rowKey配置
<ProTable rowKey="id" ... />

// 检查onClick中是否正确设置currentRow
onClick={() => {
  console.log('record:', record);
  setCurrentRow(record);
  setStepFormVisible(true);
}}
```

### 问题2：API返回401未授权
**现象**：Network请求返回401状态码

**可能原因**:
1. Token过期
2. 未登录
3. 权限不足

**解决方法**:
- 重新登录
- 检查权限配置
- 检查@PreAuthorize注解

### 问题3：API返回数据但表单未填充
**现象**：console显示数据加载成功，但表单仍为空

**可能原因**:
1. 字段名不匹配
2. form.setFieldsValue未生效
3. 数据格式不正确

**解决方法**:
```typescript
// 检查字段名是否匹配
<Form.Item name="productName"> // ← 必须与data中的key一致
  <Input />
</Form.Item>

// 检查data是否正确传递
useEffect(() => {
  console.log('收到data:', data);
  if (data) {
    console.log('设置表单值:', data);
    form.setFieldsValue(data);
  }
}, [data]);
```

### 问题4：子表查询返回空数据
**现象**：主表数据加载成功，但子表数据为空

**可能原因**:
1. 数据库中没有对应的子表数据
2. msds_id字段值不匹配
3. SQL查询条件错误

**解决方法**:
```sql
-- 检查子表数据是否存在
SELECT * FROM msds_hazard WHERE msds_id = 164;

-- 检查关联关系
SELECT m.id as main_id, h.msds_id as hazard_msds_id
FROM msds_main m
LEFT JOIN msds_hazard h ON m.id = h.msds_id
WHERE m.id = 164;
```

### 问题5：前端编译错误
**现象**：页面白屏或控制台有React错误

**可能原因**:
1. 导入路径错误
2. 组件语法错误
3. TypeScript类型错误

**解决方法**:
- 检查浏览器控制台的错误信息
- 检查前端编译日志
- 运行 `npm run build` 查看编译错误
